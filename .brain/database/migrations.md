# Database Migrations

## Generic groups migration (2026-10-01)

`0005_friendly_celestials.sql` adds default-empty JSONB groups, its GIN index,
and the project/actor/time index. Generated with `bun run db:generate --local`,
reviewed and applied with `bun run db:migrate --local`. Local PostgreSQL fixture
checks pass. Production application remains pending release; existing events
receive empty groups and no identity backfill is attempted.

## Workflow

- Generate migrations from the Drizzle schema.
- Review generated SQL before applying it.
- Apply changes through package scripts; do not hand-edit migration history.

## Current State

The initial migration is generated at
`packages/db/drizzle/0000_slimy_chameleon.sql`. It creates projects, scoped
project keys, immutable events, and daily rollups with their foreign keys and
indexes.

The reviewed second migration is generated at
`packages/db/drizzle/0001_sturdy_harry_osborn.sql`. It adds Better Auth user,
session, account, and verification tables plus the admin-plugin role/ban
fields.

The reviewed third migration is generated at
`packages/db/drizzle/0002_colossal_zombie.sql`. It creates organizations, adds
the indexed required organization foreign key to projects, seeds the default
`Personal` organization, and backfills every existing project before enforcing
the non-null constraint.

## Production State

- A standalone Neon database named `logly` was created from the Vercel Storage
  dashboard on the free `iad1` plan with Neon Auth disabled.
- The storage resource was deliberately not connected to the application, so
  Vercel did not add Neon's generated environment-variable bundle.
- Only the pooled connection URL is stored as the Logly project's Production
  `DATABASE_URL` secret. The credential itself is never recorded in Brain.
- All four reviewed migrations are applied to production. Deployment
  preparation
  reruns the idempotent migration command before the dashboard build.
- The guarded initial owner bootstrap completed after migration; its temporary
  environment inputs were removed and are not part of the runtime deployment.
- A verified backup-and-restore exercise remains required.

## Mobile platform migration

`0004_long_warbird.sql` adds nullable `analytics_events.platform`, `analytics_events.app_version`, and `analytics_events.app_build` columns. Drizzle generated the SQL, journal, and snapshot. It applied successfully to local PostgreSQL, where the guarded SQL fixture verified Android/iOS sessions, installations, events, releases, platform filters, and mobile country visits. Existing event rows require no backfill.

## Breakdown index migration (2026-11-12)

`0006_breakdown_indexes.sql` adds the two indexes listed in the schema doc.
Generated by Drizzle (SQL, `0006_snapshot.json`, journal entry), after and
dependent on the unreleased `0005_friendly_celestials.sql`. Applied only to a
disposable local test database by the breakdown SQL fixture test; not applied
to the shared local or production databases. The statements use plain
`CREATE INDEX`, which blocks writes to `analytics_events` while building; on a
large production table, consider running them `CONCURRENTLY` out of band first.

## Tracking-quiet alerts migration (2026-11-24)

`0007_tracking_quiet_alerts.sql` creates `analytics_tracking_alert_state` and
`analytics_tracking_alerts` with their FKs and indexes (new, empty tables; no
locks on `analytics_events`, no backfill). Generated by Drizzle (SQL,
`0007_snapshot.json`, journal entry), after `0006_breakdown_indexes.sql`.
Applied to the shared local database (together with the previously unapplied
`0006`) for QA, and to a disposable schema by `pages-alerts.sql.test.ts`. Not
applied to production; `deploy:prepare` applies it at the coordinated release.
Run the SQL fixtures with
`LOGLY_SQL_TEST_DATABASE_URL=postgresql://…@127.0.0.1:55438/logly_test`
(the local `logly_test` database exists).

## Deploy markers migration (2026-11-24)

`0008_deploy_markers.sql` creates `analytics_releases` with its FK, unique
`(project_id, environment, version)` index and `(project_id, deployed_at)`
index (new, empty table; no locks on `analytics_events`, no backfill).
Generated by Drizzle (SQL, `0008_snapshot.json`, journal entry) after `0007`.
Applied to the shared local database (with `0009_passkeys`) for QA and to a
disposable schema by `releases.sql.test.ts`. Not applied to production;
`deploy:prepare` applies it at the coordinated release.

## App-version adoption (2026-11-24)

No migration. Feature 4 reads the existing `analytics_events` columns
`source`, `platform`, `app_version`, `app_build`, `visitor_key` and
